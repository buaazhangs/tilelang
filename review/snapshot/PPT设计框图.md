## 0. 总览

### 0.1 因果链（整场主线）

```
FlashAttention 一轮要经过多道工序、多台机器
  → 一道一道串行做，大部分机器在空等                      （利用率低）
  → 要让机器同时忙：拆块、重叠，并为数据留出"货位"          （重叠需要安排）
  → 由谁来安排？
      GPU：工头运行时见缝插针，不依赖事先估计
      昇腾：只能照一张事先排好的排班表执行                  （排班表决定性能）
  → 排班过去靠人，现在由 TileLang 编译器承担                （职责划分）
  → 编译器把排班写成一道题：
      节拍 II → 变量 k、r、b → 三类规矩（等料、货位、互斥）  （建模）
  → II 与其他未知数相乘，直接求解通常更难 → 固定 II 后判断能否排出，再二分 II   （求解）
  → 排班结果落地成能运行的代码 → 展开 13 个任务估算收益     （落地与收益）
  → 用户只写计算和任务块，"排顺序、定货位、插交接"都交给编译器  （易用性）
```

### P01　空闲（开头，0.5 分钟）

- **核心结论**：同一个算法，在硬件上跑得快还是慢，关键在于机器有没有闲着。
- **前置知识**：无。
- **布局**
  - 居中大标题："让昇腾的机器不闲着"。
  - 副标题："TileLang 昇腾后端 AutoSchedule 的模调度设计"。
  - 下方是一幅工厂剪影：三台机器（蓝、橙、绿）并排，其中两台头上冒出 "zzz"。

### P02　工序（2 分钟）

- **核心结论**：FlashAttention 的一轮循环要经过 5 道工序，用到搬运、矩阵、向量 3 类机器。
- **前置知识**：attention 的公式（听众熟悉）。
- **布局**
  - 上部是一条公式：`O = softmax(Q·Kᵀ / √d)·V`。旁边一张小图：Q 固定一块，K/V 被切成若干块，一块一块滑过。（符号 N 留到 P10 再引入。）
  - 中部是 5 张工序卡，从左到右用箭头相连：
    ① 算相关性（QK）
    ② 更新归一化状态（online softmax）
    ③ 转交权重（pack_p）
    ④ 加权求和（PV）
    ⑤ 更新输出（accumulate）
  - 下部是三台机器图标：橙色矩阵机用连线连到 ① 和 ④；绿色向量机连到 ② 和 ⑤；蓝色搬运机单独占一列，用蓝色箭头连到各卡片之间的"进料 / 出料"处。
  - 两条自环形式的小虚线回边：
    - ② 第 n 轮 → ② 第 n+1 轮，标注"最大值、归一化系数"；
    - ⑤ 第 n 轮 → ⑤ 第 n+1 轮，标注"输出 O"。
    - 本轮 ② 传给 ⑤ 的重缩放系数沿主链走，不另画线。
  - 角落小字："Q 的预装和最终写出在循环外。"
- **动画**
  - （点击 1）公式和分块小图出现。
  - （点击 2）5 张卡片依次从左到右出现。
  - （点击 3）三台机器图标和连线出现，突出"一台矩阵机服务两道工序"。
  - （点击 4）两条跨轮回边出现。
- **页内衔接**：从算法公式讲到"每一块 K/V 都要做一遍这 5 步"，再讲到"这 5 步落在哪些机器上"。
- **跨页衔接**：底部写"下一问：这些机器都忙起来了吗？"

### P03　产能（1.5 分钟）

- **核心结论**：一道一道串行做时，机器大部分时间都在空等。按参考材料中的耗时估计，矩阵机只有约 23% 的时间在忙。
- **前置知识**：P02 的 5 道工序和 3 类机器。
- **布局**
  - 左侧 2/3 是串行甘特图，三条泳道（搬运 / 矩阵 / 向量），画两轮。每一轮按工序顺序前后串起来，同一时刻只有一条泳道有色块，其余位置是灰色斜线。
  - 只在矩阵和向量两条泳道的右端标出忙碌时间占比：矩阵约 23%，向量约 24%。搬运泳道不标百分比，因为它是好几条搬运通路的合计，不代表单台机器。这些数字是理想估算，依据和 P18 的耗时一致。
  - 右侧 1/3 是"产能"框：
    - 实际 TFLOPS = 运算量 ÷ 时间。
    - 算力达成率 = 实际 TFLOPS ÷ 同精度峰值。
    - MFU 是按模型的有效运算量计算的相关指标，本报告不展开。
    - 下面一条 100 格的条（标注"示意"），标题是"矩阵机忙碌时间占比"，只有 23 格是亮的。
    - **不要**在这条格子条和 TFLOPS 比值之间画等号或"等价"箭头。
- **动画**
  - （点击 1）甘特图出现。
  - （点击 2）灰色斜线区域闪烁高亮，标签"空等"。
  - （点击 3）右侧产能框和格子条出现；格子条用箭头连到矩阵泳道的"23%"。
- **页内衔接**：先从图上看到"空等"，再说明衡量产能的指标；矩阵机的忙碌占比低，是算力达成率低的直接原因之一。
- **跨页衔接**：底部写"下一问：怎么让机器不等？"

### P04　重叠（1.5 分钟）

- **核心结论**：让相邻几轮错开、同时进行，可以填满空档；但这要求同一种数据同时有好几份在场，所以需要"货位"（缓冲区份数）。
- **前置知识**：P03 的串行甘特图。
- **布局**
  - 沿用 P03 的甘特图。
  - 右侧是一个货架图标，画 2 个格子。
  - 底部一句话："只改变时间安排，不改变数学结果。"
- **动画**
  - （点击 1）只将第 2 轮的搬入色块向左平移，插进第 1 轮的计算时段；后续计算仍保留其数据依赖。画面突出“第 2 轮搬入与第 1 轮矩阵乘重叠”，不将整轮工序整体平移。灰色区域减少。
  - （点击 2）一个红色叹号出现：第 2 轮的 K 料到了，可第 1 轮的 K 还在用，放在哪？

- **页内衔接**：先解决"错开"，再看错开带来的新问题，最后由货位解决这个问题。
- **跨页衔接**：底部写"下一问：谁来安排这些重叠？GPU 和昇腾的答案完全不同"。

### P05　工头（1.5 分钟）

- **核心结论**：GPU 的主语是工人。每个工人拿一份从头到尾的工单，自己去用机器；工头每一拍从就绪的工人里挑一个放行。
- **前置知识**：P02 的工序，P04 的重叠。
- **布局**
  - 一个 GPU 车间的俯视图。
  - 左侧是一排工人（人形，标 warp），每人手里一张小工单："①→②→③→④→⑤"。
  - 中间门口站着工头（哨子人形，标 warp scheduler）。
  - 右侧是机器区（矩阵机、向量机、搬运口），由所有工人共用。
  - 底部是"就绪"三条件图标：📦 料到了、⚙ 机器能收、🚧 没在开会（barrier）。
- **动画**

  - （点击 2）工头出现，用箭头指向一个工人，旁边写"每一拍放行一个就绪的工人"。
  - （点击 3）三个就绪条件依次出现。
- **跨页衔接**：底部写"下一问：有工人卡住时会怎样？"

### P07　排班（2 分钟）

- **核心结论**：昇腾的主语是机器。机器各自独立；一个调度员拿着一张事先排好的排班表，按顺序把活投进各台机器的队列；机器按队列顺序做，彼此之间用信号灯交接。
- **前置知识**：P05、P06 的 GPU 作为对照。
- **布局**
  - 一个昇腾车间。
  - 左侧是调度员（拿夹板的人形，标 Scalar），手里一张排班表。
  - 右侧三台机器，每台前面有一条队列，队列里的工单卡片按顺序排好。
  - 机器之间画红绿灯。
  - 顶部用一行对比条呼应 P05："GPU：给工人发工单 ｜ 昇腾：给机器排班"。
- **动画**
  - （点击 1）调度员和排班表出现。
  - （点击 2）卡片依次从排班表飞进各台机器的队列。
  - （点击 3）演示一次交接：搬运机做完 → 信号灯变绿 → 矩阵机开始。
  - （点击 4）对比条出现。
- **页内衔接**：先讲"谁发活"，再讲"机器怎么接活"，最后讲"机器之间怎么交接"。
- **跨页衔接**：底部写"下一问：排班表定下来以后，执行时还能变吗？"

### P08　负担（1.5 分钟）

- **核心结论**：顺序是静态的，只有"具体哪一刻开工"由信号灯决定。排班表排得不好，机器就会白等。所以这张表的好坏直接决定性能，而它过去要靠人来排。

### B1　单调性（备份）

- **问题**：为什么可以对 II 做二分？
- **论证**（只在基础模型下成立：等待时长 ≥ 0，0 ≤ r < II）：
  1. 取 II 下的一组可行解，保持 k、r、b 都不变，把 II 加 1。
  2. 数据约束可以写成 `c · II + (r_v − r_u) ≥ 等待时长`，其中 c = k_v − k_u + d 是整数。
  3. 因为 r_v − r_u < II，如果 c ≤ −1，那么 c·II + r_v − r_u < 0，与"等待时长 ≥ 0"矛盾，所以 c ≥ 0。于是 II 增大时，这条约束不会被破坏。
  4. 资源约束中，本轮那一条与 II 无关；绕回那一条是 `r_i + II − r_j ≥ …`，II 越大越松。
  5. 容量约束与 II 无关。
- **说明**：这个论证不覆盖所有工程配置，也不代表求出的是全局最优。
